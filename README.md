# თაღლითობის აღმოჩენა — IEEE-CIS Fraud Detection (Kaggle)

## მოკლე მიმოხილვა — Kaggle-ის კონკურსი

კონკურსი არის https://www.kaggle.com/competitions/ieee-fraud-detection . ეს რეპოზიტორია აერთიანებს თაღლითობის ამოცანაზე ჩატარებულ მოდელურ ექსპერიმენტებს, სადაც ეტაპობრივად შევადარეთ Logistic Regression, XGBoost, Random Forest და AdaBoost. მთავარი მიზანი იყო არა მხოლოდ მეტრიკის გაუმჯობესება, არამედ preprocessing pipeline-ის გამართული აწყობა, რათა train და test ეტაპებზე მონაცემთა დამუშავება თანმიმდევრული და საიმედო ყოფილიყო.

## Logistic Regression ექსპერიმენტი

Logistic Regression გამოვიყენე როგორც საწყისი baseline მოდელი, რომ შემეფასებინა მონაცემთა დამუშავების ხარისხი, feature engineering-ის ეფექტი და მოდელის საბაზისო ქცევა. ეს ეტაპი იყო საკონტროლო წერტილი, რომლის ფონზეც შემდეგი, უფრო ძლიერი მოდელების შედეგები შევადარე.

მონაცემთა გაწმენდისას დადგინდა, რომ dataset შეიცავდა დაახლოებით 434 სვეტს და მათ ნაწილში missing მნიშვნელობების ძალიან დიდი წილი იყო. ამიტომ წაიშალა 12 სვეტი, სადაც missing მნიშვნელობები 90%-ს აჭარბებდა, ხოლო დარჩენილ სვეტებში missing მონაცემები შევავსეთ მარტივი წესით: რიცხვით სვეტებში მნიშვნელობით -999, კატეგორიულ სვეტებში მნიშვნელობით "missing". ეს იყო სწრაფი baseline გადაწყვეტა, თუმცა აღვნიშნე, რომ Logistic Regression-ისთვის ასეთი სქემა იდეალური არ არის.

Feature engineering ეტაპზე დავამატეთ რამდენიმე სასარგებლო ნიშნული. TransactionAmt-ზე გამოყენებული log ტრანსფორმაცია skewness-ის შესამცირებლად და სტაბილურობის გასაზრდელად. TransactionDT გარდავქმენი დროით ნიშნულებად, კერძოდ საათებსა და დღეებად. ელფოსტის დომენიდან გამოვყავით prefix, ხოლო card1, card2, card3 და card5 სვეტებზე გამოვიყენე frequency encoding, რომ მოდელს მიეღო ინფორმაცია მნიშვნელობების გავრცელების სიხშირეზე.

კატეგორიული ცვლადების დამუშავებისას დაბალი cardinality-ს სვეტებზე გამოვიყენე Label Encoding, ხოლო მაღალი cardinality-ს სვეტები, მაგალითად DeviceInfo, ამოვიღეთ. ეს გადაწყვეტილება მივიღე იმიტომ, რომ One-Hot Encoding გამოიწვევდა feature explosion-ს და Logistic Regression-ისთვის გააუარესებდა ეფექტიანობას.

ამ მოდელისთვის feature scaling აუცილებელი აღმოჩნდა, ამიტომ გამოვიყენე StandardScaler. მიზეზი იყო ის, რომ Logistic Regression მგრძნობიარეა feature-ების მასშტაბის მიმართ და სკეილინგის გარეშე შედეგები შესამჩნევად უარესდებოდა.

ჰიპერპარამეტრებში შევამოწმე რეგულარიზაციის პარამეტრი C. C=0.01-ზე ROC AUC იყო დაახლოებით 0.828, C=0.1-ზე დაახლოებით 0.836, C=1-ზე დაახლოებით 0.840, ხოლო C=10-ზე დაახლოებით 0.841. C-ის გაზრდა იძლეოდა გაუმჯობესებას, თუმცა სხვაობა მცირე იყო და საუკეთესო შედეგი მივიღე C=10-ზე.

მოდელი შევაფასე ROC-AUC მეტრიკით და train/validation ქულები ერთმანეთთან ახლოს აღმოჩნდა, ამიტომ გამოხატული overfitting არ დაფიქსირდა. მიუხედავად ამისა, შედეგიდან ჩანს underfitting, რადგან Logistic Regression ვერ აღწერს ამ მონაცემში არსებულ რთულ არაწრფივ დამოკიდებულებებს.

Logistic Regression-ის ყველა ექსპერიმენტი დალოგილია MLflow-ში, მათ შორის სხვადასხვა C მნიშვნელობით გაშვებული რანები, train და validation მეტრიკები და საუკეთესო მოდელის არტეფაქტი. ამ ეტაპის საბოლოო დასკვნა არის ის, რომ მოდელი სტაბილურია, მაგრამ სუსტი გამოხატვის უნარის გამო baseline-ად რჩება და შემდეგი ნაბიჯი უფრო ძლიერი მოდელების, მაგალითად XGBoost-ის გამოყენებაა.

## XGBoost ექსპერიმენტი

XGBoost ავირჩიე Gradient Boosting მიდგომის წარმომადგენლად, რადგან ის უკეთ უმკლავდება არაწრფივ დამოკიდებულებებს და რთულ feature interactions-ს, ვიდრე ლინეარული მოდელები. ეს ექსპერიმენტი იყო მთავარი ნაბიჯი baseline შედეგების მნიშვნელოვანად გასაუმჯობესებლად.

მონაცემთა გაწმენდის ნაწილში შევინარჩუნე იგივე baseline წესები, რაც Logistic Regression-ში, რათა შედარება სამართლიანი ყოფილიყო. წაიშალა 90%-ზე მეტი missing მქონე სვეტები, ხოლო დარჩენილი missing მნიშვნელობები შეივსო -999-ით რიცხვით სვეტებში და "missing"-ით კატეგორიულებში. ეს მიდგომა XGBoost-სთვის მისაღებია, რადგან tree-based მოდელები missing-ებს შედარებით ბუნებრივად ამუშავებენ.

Feature engineering უცვლელად დავტოვე: TransactionAmt_log, TransactionDT-ის დროითი ნიშნულები, email prefix parsing და card სვეტების frequency encoding. ამ ნიშნულების მიზანი იყო მომხმარებლის ქცევის pattern-ების ამოღება და მოდელისთვის დამატებითი ინფორმაციის მიწოდება.

კატეგორიულ სვეტებზე გამოყენებული იყო Label Encoding ყველა ველში და Logistic Regression-ისგან განსხვავებით მაღალი cardinality-ს სვეტები აღარ ამომიღია. ამის მიზეზი იყო ის, რომ XGBoost უკეთ ამუშავებს ასეთ ნიშნულებს და შესაძლებელია მნიშვნელოვანი fraud სიგნალების შენარჩუნება.

XGBoost-ისთვის feature scaling არ გამომიყენებია, რადგან ეს მოდელი feature-ების მასშტაბზე სენსიტიური არ არის. შედეგად preprocessing უფრო მარტივი და სწრაფი დარჩა.

საწყის baseline ტრენინგში გამოვიყენე პარამეტრები n_estimators=200, max_depth=6, learning_rate=0.1, subsample=0.8 და colsample_bytree=0.8. შედეგი იყო Train ROC AUC დაახლოებით 0.95 და Validation ROC AUC დაახლოებით 0.94, რაც Logistic Regression-ის დაახლოებით 0.84 შედეგთან შედარებით აშკარა გაუმჯობესებაა.

ჰიპერპარამეტრების ტიუნინგში ცალ-ცალკე შევაფასე max_depth, learning_rate და n_estimators. max_depth=4 იყო underfitting, max_depth=6 ბალანსირებული, ხოლო max_depth=8-ზე overfitting-ის ნიშნები გაჩნდა. learning_rate=0.05 იძლეოდა ნელ სწავლებას, 0.1 სტაბილური იყო, 0.2-ზე კი შედეგი უმჯობესდებოდა, თუმცა იზრდებოდა overfitting-ის რისკი. n_estimators=100 იძლეოდა underfitting-ს, 200 იყო სტანდარტული, 400-ზე შედეგი უმჯობესდებოდა, მაგრამ ასევე იზრდებოდა გადამეტებული მორგების ალბათობა.

საბოლოო კონფიგურაციად ავირჩიე max_depth=6, learning_rate=0.2 და n_estimators=400, რადგან validation-ზე უკეთესი შედეგი მომცა და უფრო ღრმა ხეებთან შედარებით overfitting ნაკლებად გამოხატული იყო. საბოლოო შეფასებაში Train ROC AUC დარჩა მაღალი, დაახლოებით 0.95+, ხოლო Validation ROC AUC დაახლოებით 0.94-0.95 დიაპაზონში, რაც baseline-თან შედარებით მკაფიო უპირატესობას აჩვენებს.

XGBoost ექსპერიმენტებიც სრულად დალოგილია MLflow-ში, მათ შორის თითოეული ჰიპერპარამეტრის რანი, მოდელების შედარებითი მეტრიკები და საუკეთესო pipeline არტეფაქტი inference ეტაპისთვის. ამ ეტაპის დასკვნაა, რომ XGBoost ამ ამოცანაში მნიშვნელოვნად აჯობებს Logistic Regression-ს, უკეთ სწავლობს არაწრფივ კავშირებს და ნაკლებად არის დამოკიდებული preprocessing-ის იდეალურობაზე.

## Random Forest ექსპერიმენტი

Random Forest გამოვიყენე როგორც bagging-ზე დაფუძნებული ensemble მოდელი, რომლის მიზანიც იყო სტაბილურობის შეფასება და overfitting-ის კონტროლი boosting მიდგომებთან შედარებით. ტრენინგამდე შევინარჩუნე იგივე preprocessing pipeline, რაც სხვა მოდელებში: missing მნიშვნელობების შევსება წესით numeric=-999 და categorical="missing", კატეგორიულებზე Label Encoding და უკვე დამტკიცებული feature engineering კომპონენტები, ანუ TransactionAmt_log, TransactionDT-დან საათებისა და დღეების გამოყოფა, email prefix extraction და card frequency encoding.

ჰიპერპარამეტრების ანალიზში n_estimators-ის ცვლილებაზე მივიღე შემდეგი ROC შედეგები: 50-ზე 0.8722, 100-ზე 0.8742 და 200-ზე 0.8749. ეს აჩვენებს, რომ ხეების რაოდენობის ზრდა აუმჯობესებს შედეგს, თუმცა ეფექტი თანდათან მცირდება. max_depth-ისთვის 6-ზე ROC იყო 0.8482 და underfitting, 10-ზე 0.8742, 14-ზე კი 0.8922, რაც მიუთითებს, რომ ამ მოდელს მეტი სიღრმე მნიშვნელოვნად ეხმარება.

max_features პარამეტრზე sqrt-მ მისცა 0.8932, log2-მ 0.8909 და 0.3-მ 0.8920, ამიტომ საუკეთესო არჩევანი იყო sqrt, რაც Random Forest-ის პრაქტიკულ ქცევასაც ემთხვევა. min_samples_leaf-ზე 1 იძლეოდა 0.8932-ს, 5 იძლეოდა 0.8935-ს და საუკეთესო იყო, ხოლო 20-ზე შედეგი 0.8916-მდე ჩამოვიდა. აქედან ჩანს, რომ მცირე რეგულარიზაცია min_samples_leaf=5 ამცირებს overfitting-ის რისკს და ინარჩუნებს ხარისხს.

საბოლოო მოდელად ავიღე n_estimators=200, max_depth=14, max_features=sqrt და min_samples_leaf=5. ამ კონფიგურაციამ მომცა Final ROC-AUC 0.8935. შედეგი სტაბილურია, მაგრამ XGBoost-ს ჩამორჩება, რადგან Random Forest არ ასწორებს შეცდომებს ეტაპობრივად boosting-ის მსგავსად და რთულ interactions-ს შედარებით სუსტად სწავლობს. ამავე დროს მისი უპირატესობაა მეტი სიმყარე noisy მონაცემებზე და ნაკლები მიდრეკილება გადამეტებული მორგებისკენ.

## AdaBoost ექსპერიმენტი

AdaBoost დავამატე დამატებითი baseline ensemble ალგორითმად, მიუხედავად წინასწარი მოლოდინისა, რომ ამ ტიპის მაღალი განზომილების და noisy მონაცემზე საუკეთესო შედეგს ვერ აჩვენებდა. ექსპერიმენტის მიზანი იყო სხვადასხვა მიდგომის ქცევის უფრო ფართო შედარება ერთნაირი preprocessing პირობებში.

ამ მოდელისთვისაც შენარჩუნდა იგივე preprocessing pipeline: missing მნიშვნელობების შევსება წესით numeric=-999 და categorical="missing", კატეგორიულ ცვლადებზე Label Encoding და იგივე engineered ნიშნულები, მათ შორის TransactionAmt_log, TransactionDT-ის დროითი ნაწილები, email prefix extraction და card სვეტებზე frequency encoding.

ტესტირება ჩატარდა ძირითადად n_estimators და learning_rate პარამეტრებზე. დაკვირვებამ აჩვენა, რომ მცირე n_estimators იწვევს underfitting-ს, ხოლო დიდი n_estimators ზრდის ტრენინგის დროს ისე, რომ ხარისხი მკვეთრად აღარ უმჯობესდება. learning_rate-ის ზრდა ზოგ შემთხვევაში აუარესებდა სტაბილურობას.

საბოლოო შედეგში AdaBoost-ის ROC AUC მნიშვნელოვნად დაბალი იყო XGBoost-თან შედარებით და პრაქტიკულად Random Forest-ის დონეზე ან მასზე სუსტი, თან ნაკლები სტაბილურობით. დასკვნაა, რომ ამ ამოცანისთვის AdaBoost ოპტიმალური არჩევანი არ არის, რადგან რთულად უმკლავდება noisy და sparse feature space-ს, სუსტად სწავლობს რთულ არაწრფივ კავშირებს და მეტად მგრძნობიარეა outlier-ებზე. მიუხედავად ამისა, ეს ექსპერიმენტი მნიშვნელოვანი იყო baseline სურათის გასაფართოებლად.

## პროექტში გამოვლენილი პრობლემები და გადაწყვეტები

პროექტის განმავლობაში გამოვლინდა რამდენიმე კრიტიკული ტექნიკური საკითხი, რომლებიც ძირითადად preprocessing-სა და pipeline-ის ერთგვაროვნებას ეხებოდა. მათი დროული გადაწყვეტა საჭირო იყო, რათა inference ეტაპზე ტრენინგის ლოგიკა ზუსტად გამეორებულიყო და შეცდომები არ დაგროვილიყო.

პირველი პრობლემა იყო categorical encoding-ის შეუსაბამობა train და test მონაცემებს შორის. თავდაპირველი LabelEncoder მიდგომა მყიფე აღმოჩნდა, რადგან test-ში ჩნდებოდა ახალი კატეგორიები და transform იშლებოდა. ეს გადავჭერი იმით, რომ encoding მთლიანად pipeline-ში გადავიტანეთ, fit მხოლოდ train-ზე კეთდება, ხოლო test მხოლოდ transform-ს იყენებს.

მეორე პრობლემა იყო feature names mismatch. ზოგჯერ ტრენინგისას იქმნებოდა სვეტები, როგორიცაა P*emaildomain_prefix, მაგრამ test-ში ისინი არ არსებობდა ან პირიქით. ასევე გვქონდა განსხვავებული naming pattern, მაგალითად train-ში id_12 და test-ში id-12, რაც იწვევდა შეცდომას "Feature names should match those that were passed during fit". გადაწყვეტა იყო სვეტების სახელების უნიფიცირება, კონკრეტულად - სიმბოლოს *-ად გარდაქმნა, და preprocessing კლასში მკაცრი კონტროლი, რომ transform ეტაპზე შეიქმნას ზუსტად იგივე სვეტები.

მესამე პრობლემა იყო test dataset-ში აკლებული სვეტები. ზოგჯერ train-ში არსებული ველები test-ში საერთოდ არ ჩანდა, რის გამოც pipeline ვერ აგრძელებდა მუშაობას. ამ შემთხვევაში transform ეტაპზე დავამატეთ კონტროლი, რომელიც ყველა საჭირო სვეტის არსებობას ამოწმებს და აკლებული სვეტების შემთხვევაში ქმნის მათ default მნიშვნელობებით, მაგალითად 0 ან "missing".

მეოთხე პრობლემა იყო XGBoost dtype error ტექსტით "DataFrame.dtypes must be int, float, bool or category". მიზეზი იყო preprocessing-ის შემდეგ დარჩენილი object ტიპის ველები. გამოსავალი გახდა ყველა categorical სვეტის რიცხვით ფორმატში გადაყვანა Label Encoding-ით, რის შემდეგაც საბოლოო მატრიცა სრულად numeric ტიპებისგან შედგა.

მეხუთე პრობლემა იყო DataFrame fragmentation warning, რომელიც ჩნდებოდა მაშინ, როცა ბევრი სვეტი ეტაპობრივად ემატებოდა. ეს შეცდომა არ აჩერებდა პროცესს, მაგრამ ამცირებდა შესრულების სიჩქარეს. პრობლემის შესამცირებლად feature engineering უფრო კომპაქტურად განვახორციელე და საჭიროებისას გამოვიყენე `.copy()` ახალი dataframe-ის შესაქმნელად.

## საბოლოო დასკვნა

მოდელების შედარებამ ნათლად აჩვენა, რომ Logistic Regression არის მარტივი baseline და ამ მონაცემზე underfitting-ს განიცდის, Random Forest არის სტაბილური მაგრამ შეზღუდული, AdaBoost აჩვენებს შედარებით სუსტ შედეგებს, ხოლო XGBoost იძლევა საუკეთესო ხარისხს. საბოლოო შედეგით საუკეთესო მოდელია XGBoost, რადგან კარგად ამუშავებს არაწრფივ დამოკიდებულებებს, ეფექტურად იყენებს feature interactions-ს და პრაქტიკაში ნაკლებადაა დამოკიდებული preprocessing-ის იდეალურობაზე, ვიდრე უფრო მარტივი მიდგომები.
